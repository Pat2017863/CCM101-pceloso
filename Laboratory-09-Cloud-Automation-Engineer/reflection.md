# Laboratory 09 Reflection: Cloud Automation Engineer

Automation is important when managing hundreds of cloud servers because doing every task manually takes too much time and can lead to human errors. By using scripts and scheduled tasks, administrators can perform repetitive activities consistently. For example, a backup script can save application data every night without requiring an employee to remember to run it. This helps improve efficiency and allows cloud engineers to focus on more important responsibilities.

However, automation also has potential dangers. A small mistake in a script can affect many systems if it runs automatically across hundreds or thousands of servers. For example, a destructive command with an incorrect directory could delete important files instead of temporary files. To reduce these risks, engineers should test scripts in a safe environment, review commands carefully, use appropriate permissions, and maintain reliable backups before deploying changes widely.

Writing a Bash script was different from creating a Docker Compose YAML file during Mission 6. Bash uses commands, variables, and conditions to tell the operating system which actions to perform. Docker Compose YAML mainly describes how containers, networks, and storage should be configured. Bash is useful for automating system tasks, while Docker Compose helps define and manage application environments. Both tools make cloud operations more organized and repeatable.

From Laboratory 1 to Laboratory 9, my understanding of cloud computing has developed from learning basic cloud concepts to practicing infrastructure setup, container deployment, storage, security, and automation. I now understand that cloud computing involves more than simply using remote servers. It also requires managing resources, protecting systems, documenting work, and making operations reliable. Keeping my work in GitHub also taught me the importance of maintaining a record of technical progress.

The role I enjoyed most was the Cloud-Native Engineer because I was interested in deploying applications with containers and learning how services work together. I also found automation useful because it reduces repetitive work. Overall, these laboratories helped me understand how different cloud engineering roles contribute to building and maintaining reliable cloud environments. I want to continue improving my scripting, troubleshooting, and deployment skills so I can apply them to real-world IT projects.
